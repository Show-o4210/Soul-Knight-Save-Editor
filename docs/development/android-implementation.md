## 构建

在仓库的 `android/` 目录使用 JDK 21：

```powershell
.\gradlew.bat testDebugUnitTest assembleDebug lintDebug
```

Debug APK 位于 `app/build/outputs/apk/debug/app-debug.apk`，使用调试签名。正式 Release 需要仓库外的签名配置，必须按[签名文档](../android-signing.md)操作；不要将密钥、密码或私有样本提交到仓库。正式签名构建关闭 Gradle 配置缓存。

## 当前能力概览

| 子系统 | 当前职责 | 重要边界 |
| --- | --- | --- |
| 游戏与渠道发现 | 保存多个游戏包名，扫描已安装渠道并选择目标 | 扫描发现不等于对应功能可编辑；一次只操作选中的游戏与 Android 用户 |
| Root / Shizuku | 为扫描、读取、备份、写入和恢复提供文件访问 | 单次操作固定访问后端；切换后必须重新读取；ADB 模式不支持私有目录 |
| 账号与分片识别 | 将 XML、物品、统计和其他来源按包名、Android 用户、账号及文件规则绑定 | 不用默认初始化分片替代账号分片；重复或不明确配对拒绝自动选择 |
| 存档格式选择 | 普通快速／专家编辑可选择 `.data` 或 `.data.new` | 按游戏、Android 用户和账号记忆；切换格式清除草稿与预览；缺失时不回退修改另一格式 |
| 快速／专家编辑 | 角色、物品、武器、皮肤、进化和神话武器等已实现业务 | 功能受游戏版本、来源文件、账号、结构及已确认目录限制；见[功能说明](../help/features.md) |
| 自由编辑 | 对选定文件解码／导出、外部编辑、匹配导入并生成写回预览 | 不提供业务字段校验或自动修复；未知格式按原始字节处理；见[自由编辑说明](../help/free-editing.md) |
| 备份与事务 | 手动备份、修改前原件、ZIP 导入／限定还原、写前检查、写后复读及失败恢复 | 不是完整游戏应用备份；目标文件缺失时不创建；见[备份说明](../help/backup-and-update.md) |

## 存档格式与读取边界

普通快速／专家模式使用用户明确选择的格式作为编辑目标。游戏实际读取来源与助手编辑目标是两个概念；助手显示可识别的读取配置，但不能保证游戏在所有渠道或状态下最终采用哪份文件。

- `.data` 与 `.data.new` 的普通编辑按所选格式读取、预览和写回，不因某格式缺失而自动回退修改另一份。
- 新格式模式保留已有读取开关；旧格式模式按当前规则将对应账号已有开关归零。缺失键不补建。
- 账号开关映射需使用已确认的游戏配置关系，不能假定开关 UID 必然等于分片文件名中的账号。
- 自由编辑按导出会话记录来源；同目录、同账号、同名配对文件只按实现支持的规则同步字段。冲突时停止预览，不猜测用户意图。
- 手动还原可选择读取开关处理方式；事务故障回滚必须恢复原始字节，不套用手动还原策略。

详细规则与样本证据见[开发状态](../development-status.md)、[本地读取说明](../help/local-data-reading.md)及[自由编辑说明](../help/free-editing.md)。

## 安全与事务原则

维护时不得轻易移除以下约束：

1. 操作前检查目标游戏已退出；检测失败也停止操作。
2. 对包名、Android 用户、账号、真实路径和来源文件进行范围校验。
3. 预览与应用之间重读来源并执行漂移检查。
4. 写入前持久化原件备份和事务状态。
5. 写入后复读校验内容与必要元数据；失败按事务恢复流程处理。
6. 写入结果不确定时不盲目重试、不跨访问视图自动重放。
7. 未知字段、非目标账号和未选择的内容应按业务规则保留；没有依据时不补建字段或推断游戏上限。
8. 合成测试、离线样本、设备读取和游戏内效果分别记录，不互相替代。

Root / Shizuku 的专项实现与验证细节见[历史验证档案](../root-shizuku-validation.md)。武器皮肤规则见[皮肤调查](../weapon-skins-8.7.0.md)，普通进化和神话武器见[进化调查](../weapon-upgrades-8.7.0.md)，角色重新锁定见[重新锁定规则](../character-relocking.md)。
