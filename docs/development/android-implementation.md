# Android 实现与构建

[开发文档索引](README.md) · [用户帮助](../help/README.md)

当前源码基于最新正式版 **`2.0.2` / versionCode 18**，GitHub 标签为 `v2.0.2`：[下载正式 APK](https://github.com/Show-o4210/Soul-Knight-Save-Editor/releases/download/v2.0.2/SoulKnightSaveEditor-2.0.2.apk) · [发布说明](../releases/2.0.2.md)。本版修复目录检查的 Root 错误分类，增加可显式选择的 Shizuku Root 通道；原生 Root 继续默认，旧用户无需安装 Shizuku，也不会自动请求其授权。

这是需要 Root 的本地存档助手。**文件读写最近测试时间为 2026 年 10 月 9 日，存档适配基准仍为元气骑士 8.6.0。** 本次在 Pixel 6 / Android 16 上验证应用自身合成目录中的文件读写、原件备份、事务恢复及 owner、mode、SELinux context；原生 Root 和 Shizuku Root 通道测试通过。未修改真实游戏存档或验证游戏内效果，OnePlus / APatch / FolkPatch 的 Issue #4 反馈仍待用户复测，**不保证实际可用**。开发候选的详细修改与测试记录见 [Root / Shizuku 验证记录](../root-shizuku-validation.md)。

设置 → 存档访问方式可选择「原生 Root（默认）」或「Shizuku Root（备选）」。Shizuku 需要另行安装并通过 Root 启动；选择后通过按钮授权、检查服务 UID 和 UserService 身份，再读取目标存档。ADB 模式会明确拒绝私有存档访问，不能作为免 Root 方案。一个操作和事务固定使用一个后端，操作中或有未完成事务时禁止切换；切换后旧快照、草稿和预览失效，需重新读取。失败诊断仅在本地展示和复制，不上传存档或日志。

上一正式源码为 **`2.0.1-rc01` / versionCode 17**，已在 [v2.0.1-rc01 正式发布页](https://github.com/Show-o4210/Soul-Knight-Save-Editor/releases/tag/v2.0.1-rc01)公开：加入 vivo 8.6.0 已确认的 16 位小写十六进制账号，统一 XML、物品与统计分片识别；原有数字账号继续保留。2026-10-04 核心回归及 vivo 私有样本离线验证通过，用户实测角色、皮肤解锁成功；其余 vivo 功能仍待游戏内验证。由预发布转正时保留已测试 APK，版本字符串仍为 `2.0.1-rc01`。2.0.2 保留这些修复；历史 `v1` 附件不包含 vivo 修复。规则、边界与验收步骤见 [vivo 适配档案](../vivo-channel-2.0.1-rc01.md)。

打开仓库的 [`android/`](../../android/) 作为 Android Studio 项目，或在该目录使用 JDK 21 构建调试包：

```powershell
.\gradlew.bat testDebugUnitTest assembleDebug lintDebug
```

Debug APK 位于 `app/build/outputs/apk/debug/app-debug.apk`，使用调试签名。正式 Release 构建读取仓库外签名配置，步骤见[签名文档](../android-signing.md)。2.0.2 正式包可覆盖同正式签名的 2.0.0 / 2.0.1-rc01；历史 alpha 和 `2.0.2-root01` Debug 候选签名不同，不能直接覆盖。请先导出内部备份并处理未完成事务，具体见[迁移说明](../releases/2.0.0.md)。

## 当前编辑范围

主界面为可扩展的“存档／角色／物品／武器”Tab，备份位于设置。存档页支持按包名正常扫描，以及主动按内容特征寻找其他渠道；每次选择一个版本，切换会清空旧扫描和草稿。详见 [alpha07 界面与搜索规则](../navigation-discovery-alpha07.md)。

| 数据 | 快速模式 | 专家模式 |
| --- | --- | --- |
| 现有角色与皮肤 | 分别一键解锁，默认关闭 | 逐项选择 |
| 现有角色等级 | 低于 7 级时提升至 7 级，默认关闭 | 按角色选择，保留高于 7 的值 |
| 已有技能条目 | 解锁未解锁条目，默认关闭 | 按已有技能选择解锁 |
| 已有宠物解锁键 | 按 8.6.0 映射一键解锁，默认关闭；`Hide` 排除 | 按已有宠物选择解锁 |
| 磁带、蓝图、设施、饰品 | 磁带 1、蓝图全部研究、设施补齐、饰品充能 100；默认关闭 | 逐项选择相同操作 |
| 材料、通用进化碎片、种子、兑换券 | 四个分类按钮，每项 +1000，可连续点击及撤销一次 | 逐项／选中批量设置目标数量或自定义增加量 |
| 小鱼干、普通／英雄试玩券 | 三个独立非负整数输入框，留空不改 | 逐项目标数量或选中批量设置 |
| 武器获取次数 | 统一 +8；已知编号武器缺失键补入，已有其他武器获取键也累加；默认关闭 | 名称／ID 搜索，所选单项或批量自定义增加量／+8 |

编辑目标为识别出的 `game.data`、PlayerPrefs XML、`item_data_<UID>_.data` 与 `statistic_<UID>_.data`。XML 单文件模式支持角色、皮肤及已有宠物键；物品可独立修改，无需 game 或角色 XML。当前物品目录只开放 `AppVersion=80600`，不把默认分片替代 UID 分片。武器独立处理统计分片，需同账号物品分片的 80600 版本核对；其他 `.data` 可进入只读备份。预览、写前漂移检查、原件备份、写后复读、失败恢复均在应用内实现。选定账号后临时记住存档路径，预览前读取最新内容，修改／恢复后自动刷新，方便连续编辑。写回完成后弹出独立结果窗口，显示成功标志；可展开查看成功项与失败原因。写回仍按整笔事务处理，不把失败的事务报告为部分成功。ZIP 仅能导出，不能导入或整包恢复。

宠物操作只处理映射表中当前账号 XML 已有的 `p<N>_unlock`；若 `game.data` 存在完整的 8.6.0 `petUnlock`，会先核对两侧状态再同步更新。格式或镜像不符时拒绝本次宠物写入。具体见 [alpha08 宠物说明](../quick-pets-alpha08.md)。

物品目录共 573 项，缺失已知 ID 可补入；已有饰品佩戴／图纸／符文保留，两个关联列表仅缺失时补空数组。具体排除项、数量及版本规则见 [alpha06 物品说明](../quick-items-alpha06.md)。

首次写入前需确认个人本地存档用途。读取、固定路径刷新、预览重读、写入、备份源读取和恢复会关闭所选游戏；查找已安装渠道的“扫描”仅作只读发现，不关闭游戏。应用不登录账号、不访问云端，也没有联网权限。

alpha12 核心实现与共用 API 见[实现档案](../core-api-alpha12.md)。快速与专家分别保留草稿；切换 Tab 不丢草稿，切换账号／游戏／重新读取或刷新存档会清空。只有当前模式草稿参与预览；预览先显示角色／物品／武器摘要，再展开逐项变化。增量按扫描原值相加，目标值明确覆盖；留空或增量 0 不改，目标值 0 清零。

2.0.0 发布前的公开核心回归为 114 项通过、4 项未注入私有样本而跳过，Release 构建、lint 与签名验证通过。发布准备时未卸载虚拟机上的旧调试助手，也未直接写真实游戏存档。此版已在 `v1` 正式发布，后续继续扩展；历史用户反馈、实际验证与尚未验收范围见[开发状态](../development-status.md)和[发布准备记录](../release-2.0.0.md)。历史档案的准备状态描述保留为当时记录，当前公开版本以发布页为准。

私有样本可用 `-PitemBaseline=<物品文件>`、`-PstatisticBaseline=<同账号统计文件>` 和 `-PunlockBaseline=<角色备份 original 目录>` 注入；不指定时对应私有回归按设计跳过。样本不应放进公开源码或 APK 资源。

vivo 组合回归可使用 `-PvivoBaseline=<私有样本目录>` 注入同账号 `game.data`、PlayerPrefs XML 和物品／统计分片。测试只在内存中计算修改并核对原文件未变，不写设备存档；未提供时该项按设计跳过。

体验与刷新 API 见[alpha13 说明](../experience-alpha13.md)：卡片问号提供说明，包名折叠后编辑，底部支持点击／滑动切换。历史 [alpha14 说明](../header-easter-egg-alpha14.md)修正标题为手指上滑收缩、下滑展开，并加入标题连点 7 次触发的 SHOWCHEER 彩蛋。alpha14 当时的 3 项彩蛋定向测试、Debug 构建、lint 与设备版本核对通过；当时未重跑完整核心回归，实际动画留待用户二测；当前验证范围以开发状态为准。

## 本地读取与 `.data.new`

正常编辑时，若所选账号的 PlayerPrefs XML 已有 `OpenRijTest_<UID>` 或 `OpenNewtonJsonTest_<UID>` 且值为 `1`，预览会列出将其设为 `0`。应用不会补造缺失键，不处理 `.data.new`，也不能保证游戏最终选择哪份进度。只有 `__UNITY_PLAYERPREFS_VERSION__` 的 XML 不具备这项操作所需的账号键。具体排查和手动核对步骤见[本地读取与 `.data.new` 说明](../help/local-data-reading.md)。

等级与技能现已支持快速和专家操作；当前游戏内未验收范围以[开发状态](../development-status.md)为准，不沿用 alpha05 的功能状态。验证前请保留原始文件。

此前维护者在部分 Root 真机环境中遇到游戏本身闪退，未修改存档时也会发生；此为特定环境观察，不是所有真机的兼容结论。测试应使用能保留并恢复原件的环境。
