# 快速模式物品功能 · alpha06

更新：2026-09-30。Android `2.0.0-alpha06` / versionCode 7。此页记录本轮最终确认的业务规则和实现边界。

## 操作范围

所有选项初始关闭，数量输入留空。重新扫描、切换账号、恢复或写入成功后清空待修改项。详细模式仍只处理角色与皮肤。

| 分类 | 确认目录数量 | 快速模式操作 |
|---|---:|---|
| 磁带 | 55 | 全部设为 `1`；缺失 ID 补入；已有较大数量也归一为 1 |
| 普通材料 | 17 | 逐项按钮每次 `+1000`，包含生物质 `material_cell` |
| 通用武器进化碎片 | 6 | 逐项 `+1000`，只含 `material_generic_weapon_fragment_0` 至 `_5` |
| 种子 | 47 | 逐项 `+1000` |
| 兑换券 | 161 | 逐项 `+1000`；英雄角色试玩券另列 |
| 小鱼干 | 1 | `materials.material_fish`，单独输入目标非负整数 |
| 普通角色试玩券 | 1 | `materials.material_ticket`，单独输入目标非负整数 |
| 英雄角色试玩券 | 1 | `tokenTickets.token_hero`，单独输入目标非负整数 |
| 蓝图 | 263 | 全部设为 `Researched`，已研究不降级，缺失 ID 补入 |
| 设施 | 6 | 在 `itemUnlock` 中补入缺少的设施，保留已有记录 |
| 饰品 | 15 | 补齐已知饰品，`durability=100`；新增条目的两个符文为 `None` |

总计 573 个确认条目，其中 231 个提供数量增加按钮。目录来自本轮本地 8.6.0 文本表与 8.3/8.6 存档结构对照，只包含名称、ID 和分类，没有参考账号的数量或原始存档。它不是官方完整物品表；无法可靠命名的磁带 `material_tape_level_2g.` 暂时跳过。

数量增加按原值计算，缺失条目按 0 计算；可连续点击并撤销单项或全部增量，直到“备份并应用”才写文件。三个直接输入框留空不改，`0` 是明确清零。没有设置猜测的游戏上限，只检查非负整数及 32 位整数溢出；这不代表游戏允许达到整数最大值。

## 饰品保留规则

- 已有 `jewelryPlayerData`、`jewelryBlueprints` **完整保留**；只有整个字段缺失时初始化为 `[]`。
- 已有饰品的符文和未知字段保留，充能设为 100；不更换角色佩戴的饰品。
- 不把旧参考账号的完整饰品、角色或其他存档状态复制过来。

## 明确不处理

技能残页、皮肤碎片、专属武器进化碎片、全部材料／活动相关条目、融合粒子等仍不明确的物品、细胞 `material_dead_cell`、瓦尔基里之羽 `material_ticket_bossrush`，以及以下八项：

- 接引大书／复苏大书：`material_c17_book_1`、`material_c17_book_2`
- 精灵之泪／法力结晶：`material_c18_book_1`、`material_c18_book_2`
- 传承族徽／便携式超时空联系装置：`material_c20_book_1`、`material_c20_book_2`
- 珍藏的番号牌／特别行动令：`material_c21_book_1`、`material_c21_book_2`

神话武器、房间装饰记录、锻造栏引用、`specialTickets` 和其他未列入目录的字段均保留原值。蓝图操作只更新蓝图状态，不修改房间装饰记录。

## 文件与账号

- 独立解析 `item_data_<UID>_.data` 的 DES/CBC + Base64 数据；按文件名中的账号匹配，不以默认 `item_data.data` 代替其他账号的分片。
- 当前物品目录只启用于 `AppVersion=80600` 的已有文件。默认模板版本 0、其他版本或不可解析文件会显示不可用；不会凭空创建整个存档文件。
- 不要求存在 `game.data` 或角色 XML。已有 `game.data` 如无 `itemData`，不补造镜像；如有镜像，必须与物品原件一致且账号唯一，才一起更新。存在但无法解析的 `game.data` 不能证明无镜像，会停止预览。
- XML 通过角色特征识别；可识别且包含所选账号已有读取开关时仍设为 `0`。不新增缺失的开关，不处理 `.data.new`。只有读取开关而没有角色特征的 XML 不会自动认领。
- 多账号可在快速模式直接选择；同账号重复物品文件拒绝自动选择。角色操作仍遵守原有 XML / game 镜像核对规则。
- 保存统一经过 `SavePlan`：扫描后漂移检查、仅变化文件原件备份、临时文件替换、权限与内容复读、失败恢复。物品可以独立保存，也可以和角色操作同一事务保存。

## 验证与待验收

本地 JVM 合成测试和私有样本离线回归覆盖：缺失 ID、重复点击增量、非法数量与溢出、全部蓝图研究、饰品佩戴／图纸／符文保留、排除项保留、无 game/XML 的物品独立修改、UID 对应、可选镜像与三文件失败恢复。真实样本只读注入，未进入源码资源或 APK。

本轮没有写回游戏存档，也没有启动游戏。离线变换与构建通过不代表游戏实载通过；仍需用户验收新增条目显示、数量显示、研究状态、饰品充能，以及重启后是否保留。

测试命令（JDK 21，使用项目 wrapper）：

```powershell
.\gradlew.bat testDebugUnitTest assembleDebug lintDebug compileDebugAndroidTestKotlin
# 可选私有样本：
# -PitemBaseline=<已提取的 item_data 文件>
# -PunlockBaseline=<既有角色私有备份的 original 目录>
```

不传私有样本时，两项私有回归按设计跳过。设备 Root 合成测试需另行显式启用，仅在助手自己的沙盒创建临时文件。
