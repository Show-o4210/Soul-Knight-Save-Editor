# 快速模式武器获取次数（alpha11）

## 实测依据

用户在 8.6.0 游戏内确认：“宁神” `weapon_361` 原为 1/6；给顶层 `object2ObtainTime` 加 8 后变为可锻造。原本该字段无键的红色 `weapon_359` 同时从按 0 计补入 8，用户也确认可锻造。旧工具使用的 `StatisticsData.WeaponGameStatisticData._weaponUsedTimes` 不作为获取次数来源。完整过程见[调查记录](weapon-forge-investigation-8.6.0.md)。

## 操作规则

- 独立“武器”Tab；快速模式提供“全部武器获取次数 +8”，默认不勾选。勾选只是待修改选择，预览并确认应用后才写回；每次完成的操作统一加 8。
- 处理范围为 8.6.0 中文名称资源中确认的 **416 个编号武器**，并合入存档已有、匹配 `weapon_[A-Za-z0-9_]+` 的其他获取记录。已知编号缺失键按 0 补入；已有次数累加，不覆盖为 8，也不猜测连续编号范围。
- 特殊武器一并增加获取次数。蓝图、科技、融合、进化及其他资格仍由游戏判断；获取次数达标不代表这些额外条件已经完成。
- 只改 `statistic_<UID>_.data` 的 `object2ObtainTime` 武器键，保留该字典的非武器项、`_weaponUsedTimes`、通关记录和其余字段。
- 统计文件不自带版本号，因此必须有同账号 `item_data`，其 `AppVersion` 为 **80600** 才开放此目录。该物品文件作为只读版本依据；武器操作不依赖 `game.data` 或角色 XML。
- 默认分片不能替代账号分片；重复路径候选、错误账号、未知获取表结构、非整数／负数／加 8 溢出均拒绝整笔操作。数据采用已验证的 DES-crst1 编解码，编码后解密复验。
- 与角色、物品页共用跨页预览、原件备份、写前漂移检查、写后复读、事务回滚和结果弹窗。版本依据文件虽不修改，也参与写前漂移检查。
- 沿用已有本地读取规则：若选定账号 XML 已有读取开关且值为 1，预览列出改为 0；不补造开关，不编辑 `.data.new`。
- 专家模式保留“武器”Tab，暂不提供逐项选择或自定义次数。快速模式的武器草稿不会在专家模式应用。

## 名称来源与覆盖边界

`WeaponCatalog.kt` 来源于已连接设备的 8.6.0 `localization.ab` 简体中文 `weapon/weapon_<数字>` 条目，资源 SHA-256 为 `dfa5677a2f9504fcce93c8da5c5b20063282dfe31a90caae92828dba257d6722`。生成脚本位于 `android/tools/generate_weapon_catalog.py`；资源原件和真实存档不进入公开源码。

非编号武器的缺失 ID 尚不自动补造，因为同一名称资源包含机关、房间、技能描述等辅助对象；该类已有获取键会正常加 8。416 项目录不等于游戏全部可锻造武器的最终名单。

## 验证方式

JVM 测试覆盖已记录和无记录武器、特殊编号武器、非编号已有武器、重复 +8、其他字段保留、版本不符、未知格式、整数溢出、账号隔离、默认文件拒绝替代，以及多文件失败回滚。可选的配对真实统计／物品样本只在内存中编辑并往返验证，不写设备。

```powershell
.\gradlew.bat testDebugUnitTest assembleDebug lintDebug `
  -PitemBaseline=<私有物品文件> -PstatisticBaseline=<同账号私有统计文件>
```

Android 界面与 Root 事务测试仅使用助手自身沙箱中的合成文件。用户已验证上述两把武器的直接存档试验；alpha11 全量操作的游戏内结果仍需验收。
