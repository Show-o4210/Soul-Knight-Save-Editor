# 2.0.5-rc02 候选 · 游戏运行检测与 Root 超时退出

2026-10-23，Android 7.0 及以上，候选版本 `2.0.5-rc02` / versionCode 27。

本轮处理游戏与助手同时运行时的存档访问问题，**尚未创建 GitHub Release**；公共最新发布仍为 [2.0.4-rc01](2.0.4-rc01.md)。继续支持已核对的元气骑士 **8.6.0 / 80600、8.7.0 / 80700**，沿用正式签名。

## 运行中的游戏先退出

访问所选游戏的实时存档前，助手检查**所选包名与对应 Android 用户**的游戏主进程及子进程，前台和后台均算运行。发现仍在运行时，停止本次存档操作，提示先保存并彻底退出游戏；不再自动强停。无法可靠确认进程状态时同样停止并显示原因，避免把检测失败当作游戏已退出。

| 操作 | 新规则 |
| --- | --- |
| 读取、刷新、重新查找当前存档 | 先检查游戏已经退出，读取完成前复查状态与文件一致性 |
| 预览普通修改、自由编辑预览 | 重读来源前检查，文件变化时重新读取并核对 |
| 自由编辑解码导出 | 检查游戏已经退出并确认源文件没有变化，再导出本轮副本 |
| 备份当前本地存档 | 检查游戏已经退出，避免备份到写入中的不同步文件 |
| 应用、还原、恢复未完成事务 | 持续按事务步骤检查；中途发现游戏启动时停止，保留需要恢复的事务记录 |
| 设置、查看／导入／导出／重命名已有备份 | 可继续使用；仅还原时访问游戏原文件并检查 |
| 打开已导出目录、外部编辑、导入副本比较 | 可继续使用；预览或应用需要重新访问来源时再检查 |

仅按 Home 回桌面或切回助手不能保证游戏退出。请先在游戏内保存；必要时到系统应用信息中手动停止对应渠道的游戏。操作期间保持游戏关闭，完成后再进入游戏核对进度。

## 文件变化与超时

运行检测与原有文件漂移检查一起使用。即便开始检查时没有游戏进程，后续重新启动游戏或来源文件改变，也不能继续沿用旧预览覆盖新进度。检测到变化后重新退出、读取并核对；自由编辑需要重新导出本轮副本。

Root 命令超时后的清理不再无限等待进程或输出流，超时会结束本次操作并恢复界面。若写入尚未完成，事务记录继续保留；先退出游戏，再按提示通过原访问方式恢复。不要为消除提示而卸载助手或清除其数据。

本轮不自动替用户结束游戏，也不能把存档变化时的每一种卡顿都认定为同一原因。后续反馈请保留具体错误和操作过程。

## 社区反馈重点

1. 游戏停留前台、切到后台、正常退出后，读取和刷新是否分别提示正确；退出后能否重试成功。
2. 多渠道共存或 Android 分身环境中，是否只限制当前选择的游戏与用户。
3. 游戏运行时，备份当前文件、应用、还原是否停止；设置、已有备份与已导出文件是否仍可使用。
4. 预览后重新启动游戏，最后应用是否能及时停止；发生超时后，界面是否恢复、能否看到明确提示。
5. 发生未完成事务时，退出游戏后能否按原通道恢复；不要公开上传原始存档或备份包。

反馈请带助手版本、游戏版本／渠道、Android 用户／是否分身、设备、Root 工具与通道，以及具体步骤和完整提示。
