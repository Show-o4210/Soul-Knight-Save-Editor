## 本次修改

- 修复正常目录判断的非零结果被误报为 Root 授权问题；明确区分目录不存在、权限拒绝、命令失败、身份失败、会话断开、超时和 I/O 错误。
- 在现有设置中增加存档访问方式、状态检查、Shizuku 授权以及本地诊断显示／复制。旧用户保持原生 Root，不要求安装 Shizuku，也不自动请求额外授权。
- Shizuku 通道使用官方 API / Provider 13.1.5 和 UserService，服务与执行进程均确认 UID 0；需要另外安装 Shizuku 并通过 Root 启动。ADB 模式不能用于游戏私有存档访问，应用不会静默切换后端。
- 两种通道复用现有扫描、识别、编辑、备份和事务恢复，保留路径、数量、大小及元数据检查；大文件经受控管道传输。操作及事务固定后端，切换后须重新读取；写入结果不确定时保留事务，停止后续写入，不盲目重发或恢复。
- 不改变存档格式、编辑范围和支持的游戏版本，不增加联网或日志上传功能。

## 安装与首次复测

1. Android 7.0 及以上，需要 Root。2.0.2 使用原正式签名，可覆盖更新正式 2.0.0 / 2.0.1-rc01；请先保留原始游戏文件和需要的助手备份。
2. 设置 → 存档访问方式，先保留默认「原生 Root」，点击「检查／重试」并在 Root 管理器中授权。这个检查只确认权限身份。
3. 如需备选通道，按 [官方说明](https://shizuku.rikka.app/guide/setup/) 安装并通过 Root 启动 Shizuku，选择「Shizuku Root」，按按钮授权并检查 UID 0 与 UserService 状态。
4. 选择正确游戏包名，先验证读取／刷新。读取会按原流程关闭目标游戏；首次排查无需写入或恢复存档。
5. 若失败，在设置中复制本地访问诊断，并反馈设备、Android、Root 工具、游戏版本、APK 版本和所选通道。不必上传存档正文；有未完成事务时先保留原后端并处理恢复提示。

历史 alpha 和 `2.0.2-root01` Debug 候选签名与正式包不同，不能直接覆盖。迁移前须导出内部所需备份并处理未完成事务；卸载会删除助手内部数据。ZIP 仍只支持导出，不能导入恢复列表或整包恢复，详见 [安装迁移说明](https://github.com/Show-o4210/Soul-Knight-Save-Editor/blob/main/docs/releases/2.0.0.md)。
