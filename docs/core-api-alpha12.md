# alpha12 核心实现与共用接口

记录日期：2026-10-01。源码基线：alpha11；本轮版本：`2.0.0-alpha12` / versionCode 13，调试签名。

这是供后续优化与用户候选验收的测试构建。正式版 V1 仍是发布里程碑，不代表功能集合已封闭；尚未进入正式发布、正式签名或全面兼容承诺阶段。

本页保留 alpha12 实现基线；alpha13 改为会话固定路径、预览前重读、写后自动刷新，最新接口与体验规则见[alpha13 档案](experience-alpha13.md)。

## 1. 本轮落地范围

| 页面 | 快速模式 | 专家模式 |
| --- | --- | --- |
| 角色 | 沿用角色、皮肤、等级至少 7、已有技能、已有宠物快捷操作 | 角色／皮肤逐项选择；逐角色等级至少 7；逐已有技能解锁；逐已有宠物解锁 |
| 物品 | 材料、通用进化碎片、种子、兑换券四组，每次各条目 +1000，可撤销一次；三个特殊整数输入保留 | 按名称／ID 搜索、分类、查看已选；数量条目设置目标或自定义增加量；所选磁带设 1、蓝图 Researched、设施补入、饰品充能 100 |
| 武器 | 确认目录与已有其他武器记录统一 +8 | 显示原获取次数，名称／ID 搜索；单项或选中批量指定增加量／设为 +8 |

数字参数先进入草稿，预览后写入。目标值覆盖扫描原值，目标 0 表示清零；增量在扫描原值上相加，增量 0 与留空不产生修改。批量输入替换所选条目的草稿参数，不在点击批量按钮时写入游戏。

数量限定非负 32 位整数，增量加法用 Long 计算并检查溢出，不推测游戏内部上限。同一物品不能同时提交目标值和增量；错误定位到 ID／名称，拒绝整份预览。四组 +1000 在所有目标校验通过后一次更新草稿，任何目标异常都不加入该组。

现有物品白名单和排除项保持有效。磁带不开放自由数量；角色不开放自由等级、回锁；武器不开放获取次数下调，也不修改科技、蓝图等其他锻造资格。饰品符文、佩戴、图纸与未知记录保留；两个关联列表仅缺失时补空。

## 2. 扫描与账号 API

源码位于 `android/app/src/main/java/com/example/soul_knight_save_editor/unlock/`。

| 接口 | 职责 | 后续维护方法 |
| --- | --- | --- |
| `SaveSource` | 目录、最大深度、文件 glob、严格文件名规则 | 新增已调查分片先登记来源，再加入业务；仅登记不意味着开放编辑 |
| `SaveLayout` | 包名／Android 用户根路径校验、由来源生成的可编辑路径范围、分片账号解析 | 不把默认分片当作 UID 分片，不放宽到任意路径 |
| `SaveScanAccess` | 停止指定应用、目录存在性、限定目录列表、读取原件 | 可接 Root 传输或隔离测试适配器；无写入方法 |
| `SaveScanner.scan` | 从适配器生成 `SaveSnapshot`，识别 XML、拒绝重复 game／XML、路径越界、过深和候选超限 | 识别规则集中在这里；已有文件读取失败不能伪装成文件缺失 |
| `RootStorage` | Root 会话、限定 find、真实路径核对、元数据／哈希校验、原子替换 | `scan` 委托 `SaveScanner`；备份扫描复用该入口；渠道发现共用路径范围与分片账号解析 |
| `EditEngine.accounts/item/statistic` | 识别账号并按文件名精确绑定唯一分片 | 重复账号分片拒绝自动选择；不按列表位置绑定 |
| `SaveInspector.inspect` | 从同一快照生成角色、等级技能、宠物、物品、武器的独立能力报告 | 无设备操作；某业务缺失不会自动禁用独立物品／武器业务 |

常规扫描仍指定包名，仅进入该应用 `files` 根目录及一级子目录、`shared_prefs` 根目录。特征发现仍是已安装应用的只读兜底，列出多个候选让用户选择一个版本；不扫描整个 `/data`，不合并不同版本存档。`.data.new` 不读取或写入。

`game.data` 没有已证明的账号标识，存在多账号时保持原有严格镜像限制。渠道发现能找到文件不代表所有功能都可编辑。重复候选、版本、结构和镜像异常继续显示原因。

## 3. 草稿、编辑与保存 API

| 接口 | 职责 |
| --- | --- |
| `UnlockSelection` | 快速全量开关，或专家角色／皮肤／等级角色／技能 ID／宠物 ID 子集 |
| `UnlockEngine.progression` | 按角色报告当前等级、已有技能与镜像可用原因；不新增缺失键 |
| `ItemChoices` / `ItemSelection` | 文本草稿与经解析的目标值／增量／已确认解锁目标；`marked` 仅表示批量选中，勾选数量条目而不填参数不会编辑 |
| `ItemDrafts.step` | 快速数量分类 +1000／撤销一次，整组预校验后返回新草稿 |
| `WeaponChoices` / `WeaponSelection` | 武器批量选中与非负增量文本；快速全量 +8 与专家逐项增量独立 |
| `ItemEngine.edit` / `WeaponEngine.edit` / `PetEngine.unlock` | 按已确认规则计算选中条目的新字节；未选记录保留；已知物品／武器缺失键按业务规则补入 |
| `EditEngine.preview` | 共用组合入口，生成所有实际变化文件；同步已有镜像与读取开关；无设备写入 |
| `SavePlan` | 文件字节输出、逐项变化与按角色／物品／武器／读取来源划分的预览摘要 |
| `SaveRepository.apply` | 停止应用、重读整个快照、漂移拒绝、持久原件备份、事务写回、复验、失败回滚／恢复 |

保留旧 `preview(..., weapons: Boolean)` 和 `WeaponEngine.addEight` 作为兼容包装，最终委托新参数入口。UI 不自行编解码存档，也不直接调用 Root 替换文件。

专家武器只允许确认目录内 ID，或当前获取表中已存在且符合武器命名的 ID。未知缺失 ID 不能创建。列表将异常计数显示为不可编辑；未选的异常计数原样保留，快速全量操作遇到异常目标仍整笔拒绝。角色专家子集只改所选等级／技能；未知角色、未知技能、缺失／不一致的目标镜像拒绝修改。

快速和专家分别保存物品／武器草稿，角色已有 `ModeChoices` 也分模式。切换 Tab 保留草稿并撤销预览；切换模式只应用当前模式草稿。切换包名、账号、重新扫描、写回成功或恢复成功清理两套草稿，要求重新扫描。后台写回期间禁用提交。

## 4. 验证与候选验收

自动验证结果在[开发状态](development-status.md)和导出的 APK 构建记录中登记。本轮重点增加分类增量原子性、选中子集、目标／增量冲突、0／空值、武器未知键／溢出、模式隔离、扫描路径／重复候选测试；继续运行已有编码、账号、漂移与恢复测试。

私有样本只通过构建参数提供，离线计算并比对原件未变，不打包到源码或 APK。本轮不直接修改真实游戏存档。按协作约定，界面与游戏效果由用户候选验收：

1. 快速材料 +1000 点两次、撤销一次，预览确认每项只 +1000；挑一项进入游戏检查。
2. 专家任选一个数量条目，先测自定义增加量，再重新扫描测目标值；检查未选条目未改变。
3. 专家选一项角色等级／技能／宠物，以及一把武器 +8；检查所选项效果与重进后的持久化。
4. 在两种模式中放入不同草稿，切换模式／Tab 核对预览范围；切换账号／游戏后确认草稿清空。

布局、名称显示、批量输入形式和更多业务仍可继续调整；用户未验收的项目不得标记为正式通过。
