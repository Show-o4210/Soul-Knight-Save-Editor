# 角色、皮肤和技能重新锁定

2026-10-23，纳入 2.0.5 候选。入口在快速／专家模式的“角色”页，通过“解锁／重新锁定”切换操作，复用共享预览、写前备份及事务恢复。

## 原值来源

1. 从现有事务原件、本地／已导入备份中，核对同包名、同 Android 用户、同账号和同 PlayerPrefs 路径。用户 0 的 `/data/user/0/` 与 `/data/data/` 只视为同一位置的别名。
2. 校验备份完整性后，按时间新到旧为每个键查找最近可确认的未解锁原值。后来的已解锁值不抹去更早的锁值；类型不符或单份备份损坏时跳过。
3. 没有原件时，只对 `com.knight.union.bili` 的已确认 8.7.0 使用内置实测参考；若取得 versionCode，还必须为 80700。角色编号与内部名的顺序也须对应，其他渠道和未知版本不套用该表。
4. 找不到可确认锁值的条目不开放重新锁定，并显示跳过原因。没有新增原锁值数据库；备份保留上限仍按用户原设置执行。

参考来自只读采集的 B 站 8.7.0 XML，采集前后 SHA-256 为 `a8bc4a5cb4fba214a7ec35f72367c96288917310e51bf4c4ffb5e133437b2c9f`。原件及账号前缀不进入源码、APK 或公共文档；内置数据只包含无账号的编号和原锁值。

| 类别 | 原样本总数 | 未解锁参考 | 值 |
| --- | ---: | ---: | --- |
| 角色 | 42 | 41 | `false` |
| 皮肤 | 792 | 749 | 29 种整数，逐键保留 |
| 技能 | 104 | 62 | `0` |

基础角色 `c0`、全部基础皮肤 `skin0` 和基础技能 `skill0` 保留。样本中的 `c23_skin3` 已为 1，没有提供其原锁值，故不列入参考；有同账号原件证明时才可能重新锁定它。

## 双文件与当前使用项

重新锁定需要角色 XML 和 `game.data`。每个目标先核对当前解锁镜像，再同时修改 `heroUnlock`、`skinLock` 或 `heroSkillUnlock`；皮肤恢复原整数，角色／技能镜像恢复布尔未解锁状态。现有读取开关继续设为 0，缺失开关不新增。

实际核对的当前选择字段：

| 内容 | `.data` 字段 | 已存在的 XML 镜像 | 回退 |
| --- | --- | --- | --- |
| 每角色皮肤 | `currentSkinDatas[HeroName]` | 无已确认镜像 | 基础皮肤 0 |
| 每角色技能 | `heroSkill[HeroName]` | `[账号_]c_<HeroName>_skill` | 基础技能 0 |
| 大厅传奇角色 | `superHeroInHeroRoom` | `[账号_]super_hero_in_hero_room` | 基础角色 0 |

锁定皮肤或技能时，仅在当前选择命中目标时回退；锁定角色时，该角色已有的非零皮肤、技能选择也回退，涉及的大厅角色选择一同处理。这只更换当前使用项，不额外锁定未选择的皮肤或技能。

回退前确认基础项已解锁且镜像一致，不替用户补造基础进度。缺省选择按已核实的 0 处理，不新增选择字段。普通当前角色没有已确认的持久化键，不创建 `chose_hero` 或 `selected_character`；游戏运行中的角色由现有退出游戏门禁处理。

已知引用发生镜像冲突时，相关目标跳过；未知字段类型不能确认安全回退时同样停止该目标。角色等级、物品数量、宠物、武器和未知字段保留。

## 验证范围

单元测试覆盖原值优先、精确参考边界、基础保留、未知锁值及镜像冲突、当前选择回退、原件哈希和账号／渠道／用户隔离。真实 B 站样本仅在内存和模拟存储中进行解锁／重新锁定往返，不写设备游戏文件。

设备回归只使用助手自身的 UUID 合成目录，验证真实 Root 两文件写入、元数据保持、重新锁定后的事务还原及界面选择。最终通过情况和 APK 校验值见[候选说明](releases/2.0.5-rc02.md)。
