# alpha08 快速宠物解锁

> 历史开发档案：以下状态、界面与测试对应标题所示版本。当前用户功能见[帮助中心](help/README.md)，当前发布与未验收范围见[开发状态](development-status.md)。

快速模式“角色”页新增“解锁已有宠物”选项，默认关闭。其目录来自 [8.6.0 宠物映射调查](pet-mapping-8.6.0.md)：57 个存档 ID 中，`Hide` 缺少官方名称资源，暂不处理；其余 56 项按映射表固定编号处理。

## 本次操作范围

- 只修改所选账号 PlayerPrefs XML 已存在的 `<UID>_p<N>_unlock`，不会创建缺失键。已为 `true` 的条目不重复写入。
- 若同时有 `game.data.petUnlock`，必须与 8.6.0 的 57 项顺序及现有 XML 键状态一致；通过后同步将对应内部 ID 设为布尔 `true`。镜像不一致或格式未知时拒绝预览，不写入。
- `game.data` 不存在或没有 `petUnlock` 时，XML 可独立处理现有宠物键。存在但格式不符的镜像不会当作缺失处理。
- 保留 `Hide`、未映射字段、玩家原有出战选择及其他文件。亲密度、技能状态和喂食数据不在本次解锁范围内。
- 与角色、皮肤、等级、技能和物品选择共享同一次预览及备份事务；已有的本地读取开关按应用既有规则处理。

## 已验证与待验证

合成样本覆盖了新宠物 `CatMecha`、`EscapeMonkey`、`Hide` 排除、XML 单文件、多账号隔离、镜像冲突拒绝、重复执行无变化，以及角色和物品一起预览。现有 8.6.0 配对备份用于只读核对 56 项并生成内存中的修改结果，未写回设备。

映射表的编号仍来自存档顺序和本地化资源的对应推断；两组历史样本使用相同的 `game.data`。用户随后反馈宠物功能在其游戏测试中正常，属于本功能的实载反馈；尚未逐个验证全部宠物、渠道特殊宠物及重启后的保留情况。
