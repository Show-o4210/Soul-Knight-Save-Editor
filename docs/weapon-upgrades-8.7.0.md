# 武器进化与神话武器：8.6.0 / 8.7.0 核对记录

核对日期：2026-10-23。下面记录本地资源、存档结构与游戏实现能确认的规则；进游戏后的实际体验继续收集反馈。

| 功能 | 8.6.0 | 8.7.0 | 保存位置 |
| --- | --- | --- | --- |
| 普通武器进化 | 118 把 | 121 把 | `weapon_evolution_data.weapons[武器 ID].Level` |
| 神话武器 | 28 把，整数 ID 0–27 | 同左 | `item_data.mythicWeapons` 列表中的 `id`、`level` |

## 普通武器进化

目录来自 `cfg.WeaponUpgrade.WeaponEvolutionConfig`，逐行核对武器 ID 和中文名称。8.7 安装包与当前热更新的表内容一致。与 8.6 相比新增：

- `weapon_018`：突击火箭（蓝）。
- `weapon_388`：神牛槌。
- `weapon_378`：激裂。

`WeaponDto.get_IsMaxUpgradeLevel` 和 `HasMeetMaxLevel` 都以 `Level > 0` 判断已完成进化；`WeaponEvolutionModule.WeaponMaxLevel` 同样确认只进化一次。因此本功能提供的是 **0 → 1**，不能套用神话武器的 3 级上限。

快速模式可完成全部确认武器的进化，专家模式可按名称或 ID 搜索、逐把选择，也可处理当前搜索结果。现有等级大于 1 的记录会保留。缺失的确认武器可以创建初始记录，皮肤索引从 0 开始、解锁皮肤列表为空；已有记录只修改 `Level`，保留 `Name`、`CurrentSkinIndex`、`UnlockedSkins` 和未知字段。进化与皮肤操作可在一次预览中组合，进化操作不消耗存档中的材料。

仅出现在皮肤目录中的武器不因此获得进化资格：是否可进化由上述专用进化表决定。目录外记录和收藏、抽奖历史等数据原样保留。

## 神话武器

实际字段大小写为 **`mythicWeapons`**；它与普通进化分片中的 `weapons` 不同，记录中的 `id` 是整数，`level` 为小写字段。

8.6 / 8.7 的 `cfg.weapon.Weapons` 都确认 `weapon_mythic_00` 至 `weapon_mythic_27`，显示名称再与对应版本本地化核对。该表中武器的 `Level=6` 是物品品质，不能拿它作为保存等级的上限。

保存等级还核对了游戏的 `MythicWeaponData` 和 `ItemData.UnlockMythicWeapon`：

- 列表没有该武器，或 `level=-1`：未解锁。
- 首次创建时 `level=0`：基础解锁。
- 重复升级逐次增加，并钳制在 3；`IsPerfect` 使用 `level > 2` 判断。因此升级可设置 1、2、3，3 为已确认的上限。

快速模式分别提供“全部基础解锁”和“全部升至 3 级”。专家模式允许逐把选择解锁或目标等级；升级操作包含解锁。只提升至选定目标，不降低更高的原等级，也不覆盖未知字段或未知整数 ID。已有列表顺序保留，新条目追加。

神话解锁和等级与“获取次数”是不同操作；本功能不会同时更改 `statistic` 获取计数。

## 数据检查与验证范围

两个目录均只接受 `AppVersion` 为整数 `80600` / `80700` 的账号物品存档。未知版本、当前版本目录外的目标及未确认等级拒绝修改。普通进化目标的 `Name`、等级和皮肤结构异常时拒绝该目标；神话目标出现重复 ID、异常等级时同样拒绝，批量操作不会跳过后静默写入其他部分。

针对性测试覆盖 0 → 1、0 / 3 级、已有更高等级、补齐记录、未知字段及 ID 保留、进化与皮肤叠加顺序、异常结构拒绝、编码后复验，以及本地 8.7 私有样例的只读预览。私有存档、资源包、反汇编文件和账号信息均不随源码分发。
