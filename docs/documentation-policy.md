# 文档维护规则

[文档总索引](README.md) · [当前开发状态](development-status.md)

本项目维护周期不固定，文档必须帮助维护者在中断一段时间后快速恢复上下文。原则是：**当前事实集中维护，历史过程保留但不冒充当前状态，无法确认的内容明确标记而不是猜测。**

## 权威来源

| 信息 | 主要事实来源 | 其他文档如何处理 |
| --- | --- | --- |
| 当前 Android 版本与 versionCode | [开发状态](development-status.md)及当前发布说明 | README、帮助和开发索引引用同一版本 |
| 用户可用功能与操作边界 | [功能说明](help/features.md) | 教程只解释操作，不复制完整功能矩阵 |
| 游戏版本／渠道兼容范围 | [开发状态](development-status.md)、对应兼容调查及[已知问题](known-issues.md) | 必须区分完整核对、基础兼容、设备读取和游戏内验收 |
| Android 架构与构建 | [Android 实现与构建](development/android-implementation.md) | 历史 API 文档标明适用阶段 |
| 存档编码、字段与账号依据 | 对应数据调查文档 | 记录样本版本、来源、未知项和适用范围 |
| 未解决问题 | [已知问题](known-issues.md) | 发布说明保留当时情况，当前状态集中更新 |
| 历史实现和发布 | alpha／dev／release 历史文档 | 不回写成当前行为；必要时加当前文档链接 |

## 状态用词

文档应区分以下证据层级，不能互相替代：

1. **实现**：代码已存在，不表示行为正确。
2. **自动测试**：单元、仪器或模拟后端测试通过，注明数量和跳过项。
3. **离线样本验证**：对合成文件或私有副本进行解析／预览，不代表设备写入。
4. **设备读取／预览**：真实设备读取或预览通过，不代表写入。
5. **文件写回验证**：真实文件写入、复读或恢复通过，不代表游戏加载。
6. **游戏内验收**：进入游戏核对效果，并注明版本、渠道、设备、条目及持久化范围。

“支持”“适配”“通过”等词必须给出明确范围。缺少证据时使用“未验证”“部分验证”或“尚待复测”。

## 更新当前状态

每次发布后：

- 更新开发状态中的版本、versionCode、发布日期和已验证范围。
- 更新发布说明，列出实际交付内容、安装要求、验证证据和未验收范围；没有记录的数据不要补猜。
- 检查根 README、帮助中心、文档索引和 Android 工程 README 的当前版本及链接。
- 将仍未解决的问题同步到 known-issues；已解决的问题保留历史记录并注明复测范围。
- 删除失效链接或改为现存的权威文档，不保留只有“请去新文档看”的多层空壳入口，除非它用于兼容外部旧链接。

## 历史文档与删除

历史文档不要求追随当前版本更新。保留仍被引用、包含独有技术依据、测试过程或决策背景的档案；对重复、空壳、失去引用且无独有价值的文件，可以删除。删除前检查仓库内链接和外部发布／Issue 引用，避免破坏仍在使用的旧入口。

旧功能状态、过时版本号和已撤销方案可以保留在历史文档正文中，但必须有明确的历史版本标记。当前索引应把当前维护入口与历史档案分开。
