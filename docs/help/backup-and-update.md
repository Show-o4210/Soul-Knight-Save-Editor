# 备份与安装更新

[帮助中心](README.md) · [图文教学](getting-started.md)

以下还原、重命名和保留上限功能从正式版 **2.0.3** 起提供；自由编辑流程见[自由编辑说明](free-editing.md)。

## 两种备份，用途不同

| 备份 | 怎么获得 | 能怎么用 |
| --- | --- | --- |
| 手动本地存档 ZIP | 设置 → 备份与恢复 → 备份当前本地存档 | 保存本次识别到的 `.data` 分片和 XML；可还原、重命名和导出；选择外部文件夹后同时导出 |
| 自动修改原件 | 每次“备份并应用”或手动还原前由助手保存 | 保存本次涉及文件的原件；新编辑备份还包含已识别的 XML，即使它当时没有变化；可还原、重命名和导出 |

<img src="../images/backups.png" alt="备份与恢复：选择外部文件夹后备份当前本地存档" width="280">

“打开文件夹”用于查看导出位置；“更换目录”重新选择位置。自动备份保存于助手内部，**卸载助手会删除内部备份、设置与草稿**；请用“导出此备份包”或“导出原件”把需要保留的内容留在外部。

这两种备份都不是完整游戏应用备份。2.0.5-rc02的手动备份包含 `.data`、`.data.new`、原生 `.data_temp`／`.data.new_temp` 恢复候选与识别到的 XML；自动原件保存本次涉及的新旧分片和 XML。公开版 2.0.4-rc01 及更早备份不包含 `.data.new`。完整应用迁移仍应另存实际游戏目录原件，见[本地读取说明](local-data-reading.md)。备份包含个人存档，不要公开分享。

2.0.5-rc02 起，备份当前本地存档、还原和恢复未完成事务都要求对应游戏已经退出。助手检测到所选包名、对应 Android 用户的主进程或子进程仍在运行时会停止，无法确认状态也会停止；请保存并彻底退出后重试。查看、导入、导出、重命名已有备份及修改设置不受此运行检测限制。

## 名称与保留上限

两类备份合并按时间显示，默认名称从“存档#0”开始递增。编号在重启、重命名和自动清理后继续递增，不重复利用已删除的编号。点“重命名”可设置自己的名称，导出文件使用该名称；不会修改备份里的原始内容或校验值。

默认不限数量。设置 → 备份保留中可填写每个游戏的保留上限，留空或填 0 表示不限。保存上限后立即清理，之后成功操作结束也会清理：手动快照与修改前原件合计，超出时删除最旧的应用内备份。未完成事务不参与清理；有未完成事务时暂停清理。外部导出副本由用户保管，不自动删除。

## 还原与导入

- **还原存档**：先自行保存并彻底退出目标游戏，助手确认其未运行后，备份即将被覆盖的当前文件，再将备份内文件写回原位置。游戏后来的本地进度会被覆盖，不再因其不同于旧事务而拒绝用户主动还原。
- 备份 XML 中对应账号已有的 `OpenRijTest`、`OpenNewtonJsonTest` 读取开关强制设为 0，即使原件为 1；默认账号使用不带 UID 后缀的键。缺失键不新增，未知类型或值会在写入前报错。备份原件保持不变。
- **导入备份 ZIP**：选择本工具导出的备份包，校验后加入应用内列表，再单独点击“还原存档”。导入本身不写游戏文件。仅支持相同游戏包名和 Android 用户的还原，不合并账号。旧版仅含分片的原件包，会尝试从当前识别的 XML 调整该分片账号的已有开关，不改其他账号。
- **恢复未完成事务**：仅在有未完成写回时出现，先按提示使用原访问方式恢复，再继续编辑。
- 失败回滚恢复到本次还原前的当前文件；进程中断后通过新事务继续恢复。自动故障恢复仍拒绝覆盖事务外变化，不会擅自覆盖游戏新进度。
- 当前是覆盖已有目标文件；缺少目标文件、目录或读取权限时会在写入前停止。不会删除备份之外的额外文件；2.0.5-rc02可原样恢复备份中的 `.data.new` 与原生临时恢复分片。

恢复完成后，进入游戏确认进度。文件恢复检查通过不等于游戏一定选用了这份存档。

## 安装正式版

从[官方 Releases](https://github.com/Show-o4210/Soul-Knight-Save-Editor/releases)下载 `.apk` 文件，在 Android 上安装，再为助手授权 Root。“Source code”是源码，不能直接作为 Android 安装包使用。Release 的好处是可以直接安装；需要自行构建的开发者看[构建文档](../development/README.md)。

当前正式发布包是 **2.0.5-rc02 / versionCode 27**，沿用已测试 APK 与正式签名，适配元气骑士 8.7.0 并保留 8.6.0。原生 Root 默认，Shizuku Root 可选；选择 Shizuku 不会免除 Root 要求。安装后先尝试读取，再看功能是否可用。

## 更新已有安装

| 原来的版本 | 更新方式 |
| --- | --- |
| 正式签名 2.0.0 至 2.0.4-rc01 或更早开发候选 | 可覆盖安装同包名、同正式签名且更高 versionCode 的 2.0.5-rc02；已装本次同一测试包无需重复安装 |
| 早期 alpha／Debug／2.0.2-root01 | 与正式包签名不同，不能直接覆盖；按下面步骤迁移 |

迁移步骤：

1. 在旧助手中处理未完成事务，导出所有需要保留的备份和原件。
2. 确认文件已经保存在**助手以外**，并另外保留自己的游戏原始存档。
3. 卸载旧助手，安装正式 APK，重新授权 Root 并选择游戏。
4. 重新读取并检查。2.0.3 起可导入本工具导出的 ZIP；旧正式 2.0.2 仍只有导出功能。

“签名不一致”不是游戏存档格式问题，不要因此先卸载游戏。正式发布标签 `v1` 对应 Android 2.0.0 里程碑；旧 Python `v1.0.1` 是另一客户端。[历史版本与迁移记录](../releases/2.0.0.md)保留详细信息。需要校验下载文件时，发布附件提供 `SHA256SUMS.txt` 和公开签名证书，构建与证书说明见[签名文档](../android-signing.md)。

**2026-10-23，模拟器测试通过，适配元气骑士 8.7.0。** B 站原生 Root 已验证材料修改与未选内容保留；其他设备与渠道继续收集问题，具体范围见[当前发布说明](../releases/2.0.5-rc02.md)。
