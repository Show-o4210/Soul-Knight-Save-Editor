# 常见问题与反馈

[帮助中心](README.md) · [图文教学](getting-started.md)

## 已经授权 Root，还是找不到存档

1. 在“设置 → 存档访问方式”点“检查／重试”，看身份和错误提示。Root 身份通过只说明拿到了执行权限，**不代表目标游戏目录已经读取成功**。
2. 确认选的是实际安装的渠道版本。多个渠道并装时，到“存档 → 查找游戏版本”点“扫描”，选中正确候选，再“读取存档”；知道包名时可用手动选择。
3. 确认助手与游戏处于同一个 Android 用户；工作资料、分身或其他用户的数据不一定可见。让游戏正常生成本地进度后退出，再读取。
4. 已找到位置但后来找不到文件时，尝试“重新查找”。只有常规刷新需要沿已记住的位置读取。

选择 Shizuku Root 时，确认 Shizuku **通过 Root 启动**、助手已授权、UserService 检查通过；ADB 模式不能用于这里的游戏私有存档。切换访问方式后需重新读取，应用不会自动切回原生 Root。有未完成事务时先通过原方式恢复。

问题仍存在时展开“查看本地诊断”，点“复制诊断”。复制不会自动发送给维护者。不要为了排查目录访问而先尝试写入。

## 读到了文件，但某个按钮是灰色的

先看该页提示和卡片“？”：可能未确认个人本地存档用途、尚未选账号、缺少对应文件／条目、版本未适配或结构不符。“物品”和“武器”有各自的来源要求，角色文件可读不代表它们也可改。

“预览全部待修改内容”还需要当前模式有实际变化，且没有进行中的操作或未完成事务。专家数量条目仅勾选、没有设置数量参数时，不会准备数值修改；只切换“只看已选”也不会新增修改。

## 数量与预期不同

“每项 +1000”是该分类中每项增加 1000，连续点击会累加草稿；“目标数量”是最终值。原有 25，增加 100 是 125，目标 100 是 100。留空不改，目标 0 清零。先展开逐项预览，错误时取消并调整输入，见[功能例子](features.md)。

## 文件写入成功，游戏里却没变化

助手确认的是文件写回与复读，不保证游戏采用了该文件。先核对游戏渠道和账号，以及游戏版本是否仍符合适配基准；保留原件和结果提示。不要连续应用更多修改来试探原因。

如果涉及 `.data.new` 或云存档，阅读[本地读取说明](local-data-reading.md)。当前没有独立的云端／本地切换按钮；缺失读取开关不会自动补造。武器获取次数也不代替特殊武器的蓝图、科技等其他条件。

## 安装时提示签名不一致

旧 alpha／Debug 包与正式包签名不同。先导出内部备份、处理事务，再迁移助手安装，详见[备份与更新](backup-and-update.md)。不要先删除游戏数据。系统拒绝降级安装时，也请检查 versionCode 和签名，而不是只看版本名称。

## 怎样反馈更容易复现

到 [Issues](https://github.com/Show-o4210/Soul-Knight-Save-Editor/issues) 描述具体过程；同类问题已有 Issue 时补充到原问题。可以复制这个模板：

```text
助手版本：例如 2.0.2（18）
游戏版本与渠道：
设备／Android 版本：
Root 管理器、访问方式：原生 Root 或 Shizuku Root
操作：在哪一页，按了什么按钮，输入了什么
预期结果：
实际结果与完整错误提示：
诊断或截图：先检查并遮盖个人信息
```

不要公开上传完整存档、真实 UID、账号、令牌或备份包。文件名和键名也请先检查个人信息；维护者如确实需要样本，再商定提供方式。

文件修改测试记录为 **2026-10-09**，不是全部设备验收日期。当前 **不保证实际可用**，OnePlus / APatch 等反馈环境仍待用户复测；最新范围见[开发状态](../development-status.md)。
