# 常见问题与反馈

[帮助中心](README.md) · [图文教学](getting-started.md)

## 已经授权 Root，还是找不到存档

1. 在“设置 → 存档访问方式”点“检查／重试”，看身份和错误提示。Root 身份通过只说明拿到了执行权限，**不代表目标游戏目录已经读取成功**。
2. 确认选的是实际安装的渠道版本。多个渠道并装时，到“存档 → 查找游戏版本”点“扫描”，选中正确候选，再“读取存档”；知道包名时可用手动选择。
3. 确认助手与游戏处于同一个 Android 用户；工作资料、分身或其他用户的数据不一定可见。让游戏正常生成本地进度后退出，再读取。
4. 已找到位置但后来找不到文件时，尝试“重新查找”。只有常规刷新需要沿已记住的位置读取。

选择 Shizuku Root 时，确认 Shizuku **通过 Root 启动**、助手已授权、UserService 检查通过；ADB 模式不能用于这里的游戏私有存档。切换访问方式后需重新读取，应用不会自动切回原生 Root。有未完成事务时先通过原方式恢复。

问题仍存在时展开“查看本地诊断”，点“复制诊断”。复制不会自动发送给维护者。不要为了排查目录访问而先尝试写入。

## Magisk 已取得 UID 0，却看不到游戏目录

部分设备的普通 `su` 与游戏处于不同挂载视图。2.0.5-rc03 保持普通 `su` 优先；仅在明确目录缺失且确认当前 `su` 为 Magisk 时，自动探测全局挂载备用，成功后在本次操作中使用该视图。无需修改 Magisk 全局设置；权限拒绝、未知错误或超时不会触发盲目重试。

2026-10-23 已在 Pixel 6 / Android 16 / Magisk 通过正式界面的读取和刷新，诊断显示“Magisk全局挂载视图”。此验证限于读取，未执行真实游戏写回或实机还原。仍失败时，请复制本地诊断，注明设备、Root 版本和所选渠道。

## 旧 Android／光速虚拟机提示“目标目录检查未成功”

部分旧 Android 环境的 `stat` 命令不支持 `-L` 参数，可能在 Root 身份检查通过后仍无法检查游戏目录。兼容修复默认先执行原命令，仅在明确报告 `stat -L` 不兼容时自动使用备用检查，无需切换设置或开启额外开关。

部分旧环境也缺少 `sha256sum`。助手默认使用系统 SHA-256 命令，仅在明确检测到命令缺失时，先自检随包的只读校验程序，通过后自动启用备用。文件完整性校验仍会执行，无需另外安装命令工具；备用自检失败时停止操作。

权限拒绝、I/O 故障及未知错误仍会停止操作，不会当作目录不存在而跳过。若仍然失败，请保留“查看本地诊断”中的阶段、退出码和错误提示。

2026-10-23 已在 Pixel 6 的光速虚拟机 Android 7.1.2、助手 2.0.4-rc01（25）、元气骑士 8.7.0 环境复现此问题。补充兼容修复后的正式签名 2.0.5-rc02（27）已通过原生 Root 与 Shizuku Root（13.5、Root 启动）完整读取，两通道均识别 8 份存档、1 个账号、42 个角色和 792 个皮肤。本次只验证读取，未对真实游戏写回或验收修改后的游戏内效果。

2.0.5-rc03 同一正式签名 APK 已在光速 Android 7.1.2 通过普通 `su` 读取回归，继续沿用上述旧命令备用方案。社区个别用户反馈的“2.0.4 可读、2.0.5 Root 超时”尚未复现，原因仍未确认；不能把本次 Magisk 修复当作该问题已解决。

## 提示游戏仍在运行，或读取时一直等待

从 2.0.5-rc02 开始，助手不再自动强停游戏。请先在游戏内保存进度并退出；仅按 Home 回桌面、切回助手或锁屏，游戏仍可能在后台运行。若退出后仍提示运行，可在系统应用信息中手动停止**所选渠道的游戏**，再回助手重试。

读取、刷新、自由导出、备份当前存档、预览、应用、还原及事务恢复会检查所选包名和对应 Android 用户的主进程、子进程。状态检查失败时也会停止并显示原因，不能用“Root 已授权”替代进程检查。设置、查看已有备份和编辑已导出的文件仍可使用。

操作期间保持游戏关闭；游戏重启或文件发生变化时，重新退出、读取并核对新内容。Root 命令超时会结束本次操作并恢复界面；如果提示未完成事务，请保留备份与事务记录，退出游戏后按原访问方式恢复，不要卸载助手或删除其数据。反馈请带完整提示、所选包名、Android 用户和操作步骤；无需公开存档。

## 读到了文件，但某个按钮是灰色的

先看该页提示和卡片“？”：可能未确认个人本地存档用途、尚未选账号、缺少对应文件／条目、版本未适配或结构不符。“物品”和“武器”有各自的来源要求，角色文件可读不代表它们也可改。

“预览全部待修改内容”还需要当前模式有实际变化，且没有进行中的操作或未完成事务。专家数量条目仅勾选、没有设置数量参数时，不会准备数值修改；只切换“只看已选”也不会新增修改。

## 数量与预期不同

“每项 +1000”是该分类中每项增加 1000，连续点击会累加草稿；“目标数量”是最终值。原有 25，增加 100 是 125，目标 100 是 100。留空不改，目标 0 清零。先展开逐项预览，错误时取消并调整输入，见[功能例子](features.md)。

## 文件写入成功，游戏里却没变化

助手确认的是文件写回与复读，不保证游戏采用了该文件。先核对游戏渠道和账号，以及游戏版本是否仍符合适配基准；保留原件和结果提示。不要连续应用更多修改来试探原因。

如果涉及 `.data.new` 或云存档，阅读[本地读取说明](local-data-reading.md)。当前没有独立的云端／本地切换按钮；缺失读取开关不会自动补造。武器获取次数也不代替特殊武器的蓝图、科技等其他条件。

2.0.5-rc02 已补齐 B 站 8.7 的新格式物品读取与写回：旧 `.data` 与 `.data.new` 可能内容不同，读取开关的 UID 也可能不同于文件账号。助手按游戏原生映射识别当前格式；含新格式时保留原读取模式，避免把其他未选进度切回旧值。当前 Android 9 虚拟机的原生 Root 已验证铁矿 7→1007，木材／电池保持 3；旧版 2.0.4-rc01 不包含这项修复，详见[实测记录](../development-status.md#b-站新格式详细验证2026-10-23)。

## 安装时提示签名不一致

旧 alpha／Debug 包与正式包签名不同。先导出内部备份、处理事务，再迁移助手安装，详见[备份与更新](backup-and-update.md)。不要先删除游戏数据。系统拒绝降级安装时，也请检查 versionCode 和签名，而不是只看版本名称。

## 怎样反馈更容易复现

到 [Issues](https://github.com/Show-o4210/Soul-Knight-Save-Editor/issues) 描述具体过程；同类问题已有 Issue 时补充到原问题。可以复制这个模板：

```text
助手版本：例如 2.0.5-rc03（28）
游戏版本与渠道：
设备／Android 版本：
Root 管理器、访问方式：原生 Root 或 Shizuku Root
操作：在哪一页，按了什么按钮，输入了什么
预期结果：
实际结果与完整错误提示：
诊断或截图：先检查并遮盖个人信息
```

不要公开上传完整存档、真实 UID、账号、令牌或备份包。文件名和键名也请先检查个人信息；维护者如确实需要样本，再商定提供方式。
