# 自由编辑：外部修改 `.data` 与 XML

[帮助中心](README.md) · [自由编辑：看图认识按钮](getting-started.md#free-editing) · [备份与还原](backup-and-update.md)

此功能从正式版 **2.0.3** 起提供，是快速、专家之外的第三个入口，没有内置文本编辑器。旧版 **2.0.4-rc01** 的实机界面和逐按钮说明见[完整图解](getting-started.md#free-editing)：2026-10-22 在 Android 9 虚拟机上演示了独立文件导出、外部编辑器选择与保存、导入比较、冲突选择和预览后取消，未执行游戏写回。不同外部编辑器与游戏内效果仍需按实际环境核对。

**2.0.5-rc02 已发布 XML 与 `.data.new` 导出／导入；旧版 2.0.4-rc01 仅导出 `.data`。** 旧图继续说明相同的目录选择、外部应用选择、导入比较和预览流程。

**2.0.5-rc02 起，读取、导出和最后写回前要求游戏已经退出。** 助手检测所选包名与对应 Android 用户的主进程、子进程；前台和后台均算运行。检测失败也会停止操作，不会当作游戏已退出。打开已导出目录、用外部应用编辑和导入副本仍可进行；预览或应用需要重新访问游戏原文件时会再次检查。导出后若进入游戏产生了新进度，先退出，再重新读取并导出，不要用旧副本覆盖新进度。

## 使用步骤

1. 保存并彻底退出游戏，在模式入口选择“自由编辑”。通过“存档”页选择游戏包名，或使用已有的渠道搜索；访问方式沿用设置中的原生 Root / Shizuku Root。
2. 点“读取文件”，选择需要导出的 `.data` 或 XML。支持 `files/` 根目录及其一层子目录；2.0.5-rc02还支持 `.data.new`，原生 `_temp` 候选仅备份、不导出编辑。本版包含 `shared_prefs/` 下所有现有 XML，默认一起选中，也可清空后只勾选 XML。自由读取不要求角色、物品目录或游戏版本通过普通编辑器的识别。
3. 选择一个本地导出目录。每次导出会创建独立的“自由编辑-时间-编号”子目录，保留既有工作目录。多个账号并存时，没有账号文件名的分片需要先选择对应的读取开关账号。
4. 点“解码并导出”。已识别的 XOR、物品／统计 DES、新格式 AES 和明文 JSON 导出为 `.json`；导入时按各自原编码重新打包。未识别编码的文件标记为“原始字节”，导出为 `.bin`，可以自行使用外部工具处理。XML 按原文导出，保留 `.xml` 后缀，不转换成 JSON。
5. 导出后请求通过**应用选择器**打开对应目录。也可点“逐文件打开（N 个）”，再为对应文件点“打开文件（选择应用）”，从支持编辑／查看的应用中自行选择。应用列表取决于已安装程序，只有一个兼容的目录处理程序时系统可能直接进入它。目标应用需要支持系统内容 URI；若目录无法打开，可逐文件打开或稍后使用“选择文件导入”。
6. 用自己的应用修改并保存，再回到助手点“从导出目录导入”。若编辑器另存到了其他位置，用“选择文件导入”，可一次选多份文件。
7. 核对导入比较，处理多份修改版本，再点“预览重新打包与写回”，最后“备份并应用”。写入后重新读取和导出，开始下一轮编辑。

返回助手或从应用选择器返回本身不会导入，也不会自动写回游戏。应用重启后可继续上次导出记录；导出记录保存在助手私有目录，不依赖外部可修改的说明文件来决定写入路径。

从 2.0.4 升级后，旧的导出记录不会凭空多出 XML；需要重新读取并创建一轮导出。目录中的 XML 带编号，例如 `003_com.example.game.v2.playerprefs.xml`，通过原有“打开文件（选择应用）”选择自己的文本编辑器即可。

## XML 原文与原路径

导入 XML 后，助手把选中的修改内容写回**该次导出记录对应的原 XML**，例如原有的 `shared_prefs/...xml`；不会根据外部文件名创建另一个游戏配置文件，也不会让外部说明文件指定新的写入路径。你修改的其他 XML 键会保留；来源含新格式时保留原读取模式，用户显式修改 `OpenRijTest`、`OpenNewtonJsonTest` 时按其修改写回。仅旧格式来源继续将对应账号已有开关归 **0**，缺失开关不补建；手动还原仍归零。

可以只选 XML 导出、修改和导入，不必为了编辑 XML 同时修改某个 `.data`。有账号的 `.data` 与 XML 混合操作仍按对应账号处理已有读取开关；不要把导出 XML 换成另一账号或另一应用的文件。基础格式通过不代表键值的游戏含义正确。

## 多余文件如何处理

- 先用导出内容的 SHA-256 比较。内容没有改变时，即使文件改名，也可以识别；同一哈希对应多个来源时，再结合名称判断，仍不唯一就列为未匹配。
- 哈希不匹配时，优先使用带编号的导出文件名前缀，例如 `000_game.data`；其次匹配原文件名前缀，例如 `game.data` 或 `game`。选择最长的有效前缀，避免把 `a.data2` 错配为 `a`。
- XML 使用相同的哈希／前缀规则；建议保留导出的编号及完整 XML 文件名前缀。
- 同一来源的多份相同内容副本视为同一个版本；只有一份不同的修改内容时，默认选择该修改版本。多份不同的修改版本不自动猜测，用户在导入比较中选择一份，或指定“本次不导入此文件”。
- 未匹配、子目录、空文件及超过单文件大小限制的文件会列出忽略原因。不会删除这些文件，也不会把它们新增到游戏目录。

导出后尽量保留编号或原文件名前缀。文件内容与名字都完全改变后，无法可靠判断来源，需要自行恢复一个可匹配的名称后重新导入。只有排版变化、内容不变的 JSON 不会重写原存档。

## 检查范围与用户责任

JSON 模式检查 UTF-8、JSON 对象格式、文件大小，以及重新编码后能否正确解码。保留未知字段、大整数和字符串，不检查角色／物品白名单、数值范围、进度组合或跨分片镜像，不替用户修复业务字段。原始字节模式不解析文件内容。

XML 模式检查基础格式，保留原文与用户修改，不提供字段级业务检查或自动修复。XML 不合法时需回外部编辑器修正并重新导入；改名为 `.xml` 也不能把任意文本变成有效配置。

**游戏是否接受自行修改后的内容，以及由此产生的游戏内异常，由用户自行承担。** 格式不合法的 JSON 会在生成写入预览前报错，可返回外部编辑器修正。格式通过不代表内容在游戏中有效。

每次写入前仍自动备份当前原件，使用原有权限保留、临时替换、复读校验、失败回滚和中断恢复。游戏在导出后改写了相关文件时，会要求重新读取和导出，避免覆盖用户尚未核对的新进度。2.0.5-rc02 在来源含新格式时保留原读取模式，XML-only 导出也保留这一状态；用户显式修改 XML 开关时按其修改写回。仅旧格式来源继续沿用对应账号已有读取开关归 0 的兼容行为，缺失键不新增。手动还原仍按备份约定归零。

自由编辑不自动修复 `game.data`、物品分片、统计分片之间的业务镜像。2.0.5-rc02 会把同目录、同账号、同文件名的 `.data`／`.data.new` 视为编码配对：只同步本次修改的 JSON 字段，保留每份文件自己的其他字段与编码；数组作为整体同步。两份同时修改且重叠字段不一致时停止预览，要求选择一致内容。未知编码的对应文件保留原样并提示，不猜测转换。

当前单文件上限 4 MiB、单次比较总量上限 64 MiB，目录比较最多 256 个文件。备份保留上限仍按设置执行；外部自由编辑目录不参与自动清理。卸载助手会丢失私有的来源对应记录，请在此之前完成写回或另行保管需要的原件。
