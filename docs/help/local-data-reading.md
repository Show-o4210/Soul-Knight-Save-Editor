# 本地 `.data`、`.data.new` 与读取开关

[帮助中心](README.md) · [图文教学](getting-started.md)

这篇说明回应 [Issue #2：已授权 Root 但未发现存档，如何处理 `.data.new`](https://github.com/Show-o4210/Soul-Knight-Save-Editor/issues/2)。下文只涉及**自己设备上的本地文件**。`.data.new` 也是设备上的文件；它的存在本身不能证明游戏正在从服务器读取，更不能证明删除它后游戏一定会改读 `.data`。

## 当前 Android 版实际会做什么（2.0.2）

- Root 扫描在**当前 Android 用户**的实际游戏包名下寻找 `files/game.data`（也检查 `files/` 的一层子目录），并在 `shared_prefs/` 寻找含角色或皮肤特征键的 PlayerPrefs XML。`/sdcard/Android/data/` 不属于这次扫描的目标。
- 只有执行已选择的角色、皮肤、等级或技能修改时，应用才会检查所选账号 XML 中**已经存在**的 `OpenRijTest_<UID>`、`OpenNewtonJsonTest_<UID>`。若它们是值为 `1` 的 `<int>`，预览会列出将其改为 `0`；值已为 `0` 则不改。缺失的键不会被补造，类型或值不认识时停止写入。
- 当前没有单独的“强制读取本地”按钮，也不读取、重命名、删除或备份 `*.data.new`。应用不登录游戏账号，不下载云存档，不能证明游戏启动后最终采用了哪个版本的进度。

项目此前将这两个键称为“本地读取开关”。**将已有的键设为 `0` 是针对已识别存档结构的兼容处理，不是对所有游戏版本、渠道和账号都有效的云端切换保证。**尤其不要为了触发这一步而随意修改角色或皮肤。

## 手动核对与修改已有开关

仅当你已确认本地 `.data` 就是想保留的进度，并且 XML 中确实有对应账号的两个开关时，才考虑以下步骤：

1. 退出游戏，完整备份**实际包名和 Android 用户**下的 `files/` 与 `shared_prefs/` 原件，包含 `.data`、`.data.new` 和 XML。助手内的“备份当前本地存档”**不包含 `.data.new`**，不能代替这一步。
2. 在备份副本中确认目标账号的 UID，检查该账号 XML 内是否存在如下 `<int>` 键。`<UID>` 是占位符，应与同一 XML 的角色/皮肤键所属账号一致，不能从文件名或 `__UNITY_PLAYERPREFS_VERSION__` 猜测。

   ```xml
   <int name="OpenRijTest_<UID>" value="1" />
   <int name="OpenNewtonJsonTest_<UID>" value="1" />
   ```

3. 如需按项目已知方式尝试本地读取，仅把**已有且属于该账号**的上述 `<int>` 键的 `value="1"` 改成 `value="0"`，保留其他 XML 内容。不要修改 `__UNITY_PLAYERPREFS_VERSION__`，也不要用另一账号的 UID。缺失键的排查见下节。
4. 将修改后的 XML 放回原位置，保持原属主和权限，启动游戏检查实际显示的进度。若进度变旧或不符合预期，先停止使用并用完整原件恢复；不要把错误状态同步为新的云端进度。

游戏可能在运行或同步时再次改写这些文件。上述方法尚未在所有渠道、版本和 `.data.new` 场景中完成游戏实载验证，因此不要把“改成 0”理解为确定的 `.data.new → .data` 迁移步骤。

## 如果找不到这两个开关

如果 XML 只有 `__UNITY_PLAYERPREFS_VERSION__`，它只是 Unity PlayerPrefs 的版本标记，**不是账号 UID 或读取开关**。先核对当前正在运行的游戏包名、Android 用户或分身环境；让游戏正常生成本地存档后退出，再重新扫描。如果仍然只有版本标记，当前 APK 无法识别该 XML 的角色/皮肤结构，也无法据此确定 UID。

如果已通过其他可靠的账号数据确认 UID，可以在**完整备份、可恢复的测试环境**中，试着向对应 XML 添加下面两条，再观察游戏是否真的改读预期的本地进度。这是尚未验证的手动排查方法；当前 APK 不会自动添加缺失键，也不能保证这两条对当前版本有效。

```xml
<int name="OpenRijTest_<UID>" value="0" />
<int name="OpenNewtonJsonTest_<UID>" value="0" />
```

也可以在完整备份后，单独测试移走或删除 `.data.new` 的影响。先保存操作前的 `files/`、`shared_prefs/` 文件清单、大小、修改时间和 SHA-256，再保存游戏启动后的同一组信息，并对照实际显示的进度；每次只改变一个条件。不要删除唯一的存档文件。**如果是在排查 `.data.new` 对本地读取的影响**，不要在这组对比测试中清除整个游戏数据或卸载游戏；如果是想从云端重新同步最新进度，应按下节的独立流程操作。这种前后对比只能帮助定位本机行为，不能仅凭文件变化断定游戏读取来源。

向项目反馈时，可提供**打码后的**包名、Android 用户、相关目录中的文件名，以及 XML 的键名列表和对比结果；不要公开上传完整存档、UID、账号标识或令牌。

## 通过云端存档同步最新 `.data`

如果希望本机 `.data` 更新为**云端账号已经保存的最新进度**，可以让游戏重新下载云存档：

1. **先确认云端进度正确。** 确保需要保留的进度已成功上传到当前游戏账号的云端，并确认自己能重新登录该账号。建议先备份设备中原有的 `files/`、`shared_prefs/` 等存档文件。**尚未上传到云端的本地进度，清除数据或卸载后可能无法找回。**
2. **清理游戏数据。** 先退出游戏，然后在系统设置中清除**游戏应用的数据**；也可以卸载游戏后重新安装。注意，**仅清除缓存**不等同于清除应用数据。
3. **登录并下载云存档。** 重新打开游戏，登录**原来的同一个账号**，使用游戏内的云存档功能下载／恢复该账号的云端进度。等待恢复完成，再进入游戏核对角色、物品等实际进度。
4. **重新读取本地 `.data`。** 退出游戏后，用本项目工具重新扫描／读取本地存档。游戏重新生成或更新的 `.data` 通常会反映这次下载的云端进度；若未找到文件或内容不一致，请先核对游戏渠道、包名、Android 用户及实际文件路径。

**注意：** 这是通过**清除本地数据后恢复云存档**来更新本地 `.data`，不是 `.data` 与云端自动实时双向同步。同步结果以**云端当时保存的进度**为准；如果最新进度只在本机、尚未上传，直接清理数据反而可能丢失它。不同游戏版本或渠道的存档文件生成时机可能有所不同。
